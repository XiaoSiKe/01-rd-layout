# 零一RD排版

## 触发与范围

只要任务会产出或修改面向 GitHub 展示的仓库主 `README.md`，先读取本 Skill，再起草或写入。上下文能确认是 GitHub 仓库时，“帮我写项目主页说明”等说法也触发，无需等用户点名。

先读现有 README（如有）和与本次改动相关的项目资料。新建、整页重写和排版任务应用下列规则。局部改动也要加载并核对相关规则，按用户授权范围编辑。若用户明确限定只改几行，保留其余内容；如整页样式偏离，只在交付时简短指出。用户当次明确要求和适用的项目约束优先。

## 排版规则

1. **主标题居中。** 全页只留一个主标题。用 `<h1 align="center">…</h1>`，在标题左侧放一个与项目有关的小图标。已有合适的正式小图标时优先沿用，否则选一个含义明确的 emoji。
2. **顶部介绍区整体居中。** 用 `<p align="center">…</p>` 排列一句话简介及需要的标语、版本徽章或章节导航。已有封面可放在居中区，保留有用的信息和现有品牌素材。正文回到常规 Markdown 左对齐，HTML 块之间用空行分隔。
3. **关键内容用紫色 Important。** 正文前段若有项目定位、使用前提或必读信息，用 GitHub 原生 `> [!IMPORTANT]`。标记独占一行，正文从下一行开始，各行保留 `> ` 前缀。提示块放在居中 HTML 区块之外，独立成块；没有关键内容时省略。

## 最小结构

```markdown
<h1 align="center">🧭 项目名称</h1>

<p align="center">用一句话说明项目能做什么。</p>

<p align="center"><a href="#安装">安装</a> · <a href="#用法">用法</a></p>

> [!IMPORTANT]
> 使用前请确认项目支持你的运行环境。

## 安装

## 用法
```

## 交付检查

确认主标题、顶部介绍区和 Important 的结构符合规则。检查新增或改动的锚点、相对路径、图标和图片替代文本，核对安装命令、版本与项目资料。可访问 GitHub 渲染时检查最终效果。纯排版任务保留原有实质内容、有效链接和安装步骤。
